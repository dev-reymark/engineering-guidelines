# UI / Design-System Rules

Before creating or materially changing UI:

1. Read `docs/design/DESIGN-SYSTEM.md`.
2. Read relevant UI/UX/accessibility/responsive documentation.
3. Inspect existing components before creating new ones.
4. Reuse existing tokens and components.
5. Do not introduce arbitrary colors, spacing, typography, radii, shadows, or breakpoints.
6. Do not create duplicate components with cosmetic differences only.
7. Follow the established visual hierarchy.
8. Preserve responsive behavior.
9. Preserve keyboard accessibility and visible focus.
10. Consider loading, empty, error, success, disabled, and permission states where applicable.
11. Do not redesign unrelated screens during a scoped feature.
12. Client-side UX validation must not replace authoritative server validation.
13. Do not sacrifice correctness/security for visual convenience.
14. Record intentional design-system changes in documentation when they affect future work.
