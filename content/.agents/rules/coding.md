# Coding Rules

- Inspect relevant code before editing.
- Make the smallest coherent change that satisfies approved scope.
- Preserve existing behavior unless change is explicitly authorized.
- Do not fix unrelated issues; document them.
- Avoid unnecessary dependencies and abstractions.
- Keep business rules explicit and testable where practical.
- Treat external/client input as untrusted.
- Never hide failures merely to make verification pass.
- Review the complete diff before completion.
