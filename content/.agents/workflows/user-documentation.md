# User Documentation Workflow

Use this workflow when creating or updating onboarding, user, admin, training, support, or developer documentation.

## 1. Establish Scope

Identify the intended audience and exact workflows being documented.

## 2. Inspect Implementation

Verify behavior from the current application, tests, configuration, and authoritative project documentation.

Do not document assumptions as facts.

## 3. Identify Documentation Impact

Determine which documents are affected:

- User Guide
- Admin Guide
- Onboarding
- Training Guide
- FAQ
- Troubleshooting
- Developer onboarding/setup

## 4. Draft from Verified Behavior

Use actual UI terminology, permissions, states, errors, and constraints.

## 5. Safety Review

Check financial, destructive, privacy, security, compliance, and irreversible operations.

## 6. Consistency Review

Ensure instructions agree with requirements, architecture, design system, code, and tests.

## 7. Verification

Walk through the documented workflow against the implemented behavior where practical.

## 8. Traceability

Record the documentation changes in the active phase result.

## 9. Stop

Do not invent or implement missing product behavior merely to make the documentation complete. Record the gap instead.
