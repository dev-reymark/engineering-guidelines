# Workflow — UI Feature

1. Read the active prompt.
2. Read `docs/design/DESIGN-SYSTEM.md` and relevant design docs.
3. Inspect existing screens/components and reuse what fits.
4. Identify the primary user task.
5. Define applicable states:
   - default
   - loading
   - empty
   - error
   - success
   - disabled
   - permission denied
6. Define responsive behavior.
7. Define keyboard/accessibility behavior.
8. Confirm server-authoritative validation/security boundaries.
9. Implement within existing tokens/components.
10. Add/update appropriate UI and behavior tests.
11. Perform visual/responsive/accessibility verification.
12. Review the complete diff for accidental redesign or duplication.
13. Update design documentation if the design system intentionally changed.
14. Update the phase result document.
15. STOP.
