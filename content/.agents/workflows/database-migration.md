# Workflow — Database Migration

1. Document why the schema change is required.
2. Inspect schema, constraints, indexes, and data assumptions.
3. Design migration and rollback/recovery.
4. Consider existing production data and deployment impact.
5. Implement only approved schema changes.
6. Verify application compatibility.
7. Test migration on representative data where practical.
8. Run full verification.
9. Record migration and rollback notes.
10. STOP.
