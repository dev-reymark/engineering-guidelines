# Responsive Design Standard

Status: Draft

## Principle

Design around content and workflows, not device names alone.

## Breakpoints

Define project breakpoints in the design system and implementation.
Avoid arbitrary one-off breakpoints.

## Layout

Document behavior for:
- navigation
- sidebars
- headers
- forms
- cards
- tables
- dialogs/drawers
- action bars
- dense operational screens

## Mobile

Prioritize:
- readable content
- touch-friendly actions
- appropriate input types
- minimal horizontal scrolling

## Tablet

Explicitly consider tablet/touch layouts for operational applications such as POS, inventory, field, and kiosk software.

## Desktop

Use additional space to improve hierarchy and efficiency, not merely to stretch content.

## Tables

Define a deliberate small-screen strategy:
- horizontal scroll
- priority columns
- responsive list/card representation
- detail drill-down

Choose based on the data and workflow.

## Testing Widths

Test representative narrow, medium, and wide layouts plus content edge cases.
Do not test only one exact device width.

## Orientation

If orientation materially affects the product workflow, test both orientations.
