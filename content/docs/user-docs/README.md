# User Documentation

This directory contains documentation for people who use, administer, support, or are trained on the product.

User documentation must describe **verified implemented behavior only**.

Do not document planned, mocked, demo-only, disabled, or unverified functionality as if it is available in production.

## Documents

- `USER-GUIDE.md` — day-to-day end-user workflows
- `ADMIN-GUIDE.md` — configuration and administrative operations
- `ONBOARDING.md` — first-time setup and adoption
- `TRAINING-GUIDE.md` — structured training material
- `FAQ.md` — recurring user questions
- `TROUBLESHOOTING.md` — verified problems, diagnostics, and recovery steps

Not every project requires every document. Keep only what is useful.

## Documentation Rule

When user-facing behavior changes, the implementing phase must determine whether these documents need updating.

Documentation is part of completion when the change affects users, administrators, onboarding, training, operations, or support.
